Diary Endpoint ve Data Model Taslağı

Mevcut projeyi ve kmpModels içindeki diary modellerini incele. Aşağıdaki üç işlem için yalnızca örnek API sözleşmesi ve ihtiyaç duyulan data modellerini hazırla:

  1. Seçilen günün sözünü oluşturma veya güncelleme.
  2. Yeni diary entry ekleme.
  3. Mevcut diary entry güncelleme.

Önerilen endpointler

PUT   /v1/diary/days/{date}/quote
POST  /v1/diary/entries
PATCH /v1/diary/entries/{entryId}

Beklenen çıktı

  • Her endpoint için HTTP methodu, path, path parametreleri ve kısa açıklama.
  • Örnek request JSON.
  • Örnek başarılı response JSON.
  • Gerekli temel hata response örnekleri.
  • KMP uyumlu Kotlin request/post-body ve response data class taslakları.
  • Hangi modellerin mevcut olduğu, hangilerinin yeni oluşturulması gerektiği.

Model kuralları

  • Request modellerini kmpModels/.../postbody altında düşün.
  • Response modellerini kmpModels/.../response altında düşün.
  • Wire modellerinde @Serializable data class kullan.
  • Mevcut EntryPostBody, EntryPatchBody ve EntryResponse yeterliyse duplicate model üretme.
  • Tarih için YYYY-MM-DD, timestamp için ISO-8601 UTC string kullan.
  • createdAt ve updatedAt backend tarafından üretilsin.
  • occurredAt olayın gerçekleştiği zamanı temsil etsin.
  • PATCH body içinde yalnız değiştirilebilir alanlar nullable/opsiyonel olsun.
  • Alan isimlerini mevcut proje modelleriyle uyumlu tut.

Kapsam dışı

Endpoint implementasyonu, controller/route kodu, Supabase kurulumu, database migration, repository, authentication, authorization, UI ve Operator bağlantısı yazma. Yeni endpoint veya ürün özelliği ekleme. Bu çalışma yalnız API örneği ve data model kararlarını netleştirsin.
